# 存储、迁移与恢复

## 数据布局

默认目录 `server/data` 可由 `LEARNLOOP_DATA_DIR` 改写。SQLite 使用 WAL 和外键，权限 0600。`originals/` 保存用户原始资料；`models/` 为本地编码模型；`runner-workspaces/` 仅用于临时隔离练习。数据库中的实体正文为规范记录；FTS、摘要及向量属于可重建派生数据。

迁移在 API/worker 启动时幂等执行：v1 旧记录保留，v2 新增证据索引及记忆状态，v3 将 JSON 向量转换为 float32 BLOB，v4 增加暂存发布与退役索引。字段索引、档案版本表使用幂等 DDL 创建。已有证据缺失时不补造历史。当前支持 macOS/Linux 的 fcntl 锁；Windows 原生部署尚未验收。

## 维护规则

| 对象 | 默认保留 | 行为 |
|---|---|---|
| cache | 7 天 | 专用目录内无符号链接的过期文件 |
| logs | 30 天 | 普通日志 |
| old-indexes / 退役向量 | 7 天 | 已发布新索引后可回收 |
| runner-workspaces | 24 小时 | 仅无活动作业时清理 |
| 完成/失败/取消的任务 | 90 天 | 去掉冗余 code/answer/checkpoint；保留任务、结果、幂等键 |
| 资料、作答、错题、评价、运行报告 | 无自动过期 | 不自动删除 |

启动和空闲时检查，每天至多一次自动清理。手动预览不是固定删除清单；执行时重新检查引用和活动任务。维护和历史索引发布共享互斥锁。向量失效不会删除其源证据。SQLite 回收页保留以便复用，因此释放逻辑空间不等于文件立即缩小；需要物理压缩时先停止服务、备份，再由维护者离线执行 VACUUM。

历史索引重建会暂存新向量，验证 active 和内容哈希后事务发布。停用记录不参与搜索，后台任务不能使其重新出现。编码失败时不发布部分新索引；全文检索继续可用。退役向量保留七天用于维护者恢复，不自动回退到内容版本不匹配的向量。清理不会访问项目外目录或链接目标。

## 备份

停止 API 与 worker 后复制整个私有数据目录及私有模型配置。运行期间应使用 Python sqlite3 的 backup API 获取一致数据库备份，不要单独复制活动中的 sqlite 文件并丢弃 WAL。导出 ZIP 用于学习记录查看和转移，包含原始资料和结构化学习数据，但不包含 API Key；它目前不是一键完整系统恢复包。

本次实施前备份在项目 `.core/before-memory-20261021-221206/`，包含源码、数据库与原私有配置。该目录被排除在分享包之外。恢复前停止服务，并把当前数据另存一份，避免覆盖近期作答。恢复旧版本时必须配套恢复旧源码和旧数据库；不要让旧代码直接修改升级后的数据库。

## 推荐恢复流程

1. 停止 API 与 worker，并保留当前源码、数据目录和 `.env` 的新备份。
2. 选择配套的数据库和源码快照，恢复到独立目录，原始资料随数据目录一起恢复。
3. 私有配置恢复到后端并设置 0600。安装对应锁文件、构建前端。
4. 用独立 `LEARNLOOP_DATA_DIR` 和本地端口启动，检查资料引用、原始作答、草稿、掌握度与复习日期。
5. 确认后再切换日常数据目录。若只有索引损坏，优先从规范原文重建，不回滚学习记录。

删除学习记录采用逻辑删除，目的是退出教学与历史检索，原始审计数据仍在本机及备份中。浏览器另有未保存草稿恢复副本；如要彻底移除某设备的学习痕迹，需同时处理浏览器站点数据和自行保存的备份。
